# Yuelin Liu — Portfolio

A personal software-engineering portfolio published at [www.liuyuelin.dev](https://www.liuyuelin.dev/). The site uses a static-first Next.js architecture and does not require a runtime backend for the portfolio itself.

## Current Portfolio

The mounted homepage is ordered as follows:

1. Hero
2. Selected Work
   - Learning & Contributions appears within Selected Work after the flagship projects, followed by Additional Work.
3. Experience
4. How I Build
5. Contact

The current static export emits these case-study routes from source data:

- `/work/moneyguard/`
- `/work/melbourne-ultimate/`
- `/work/alex/`

## Architecture

- Next.js 16 App Router with React 19.
- Fully static production output through `output: "export"`, written to `out/` with trailing-slash routes.
- Route-owned metadata for the homepage and each case study.
- Static `robots.txt` and `sitemap.xml` generated by `app/robots.js` and `app/sitemap.js`.
- Static case-study pages generated from approved source data.
- No API route, server-side rendering runtime, ISR, middleware or application backend is required to serve the portfolio.

`app/page.jsx` owns the homepage route and metadata. `src/App.jsx` is the client boundary for navigation, motion, contexts and local interactions.

## Content Model

Current public content is maintained in these authoritative files:

- `src/constants/constants.js` — Hero, Contact and How I Build content.
- `src/constants/experiences.js` — rendered experience entries.
- `src/constants/projects.js` — homepage flagship, learning and supporting-work entries.
- `src/constants/caseStudies.js` — case-study routes, metadata and page copy.

Public claims are kept evidence-bounded. Changes should preserve the distinctions between verified work, owner-attested facts, learning material and stated limitations.

## Case Studies

`app/work/[slug]/page.jsx` is the reusable static case-study renderer. `CASE_STUDIES` in `src/constants/caseStudies.js` supplies the approved slugs and content; `generateStaticParams()` emits one route per slug, `dynamicParams = false` prevents unknown slugs from generating content, and each page owns its metadata.

Homepage entries link to case studies through `caseStudyHref`. The sitemap derives the same canonical route set from `CASE_STUDIES`.

## Development

Install dependencies:

```bash
npm ci
```

Run the development server:

```bash
npm run dev
```

Run lint:

```bash
npm run lint
```

Build the static export:

```bash
npm run build
```

Verify the generated static output after building:

```bash
npm run verify:static
```

Serve `out/` locally on port 4173:

```bash
npm run preview
```

## Verification

`scripts/verify-static-output.mjs` checks the built files under `out/`. At a high level, it protects:

- meaningful prerendered homepage and case-study HTML;
- the exact approved case-study route set;
- route metadata, canonical URLs, sitemap and robots output;
- required public assets, including the resume PDF and social/project images;
- evidence-bounded public wording, attribution and stated limitations.

The script is a deterministic static-output gate. It does not provide full automated browser, interaction, accessibility, responsive or visual-regression coverage.

## Deployment

`next build` writes the static site to `out/`. `vercel.json` configures Vercel to publish that directory, so deployment serves generated files without a portfolio application server.
